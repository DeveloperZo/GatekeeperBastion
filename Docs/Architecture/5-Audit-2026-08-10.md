Scope: `Assets/Scripts` (108 files), `Assets/Tests`, `Docs/`. Prompted by Zo's request for a
full audit against the ruleset before re-cutting M42 as the code-cleanliness milestone.

**Headline: the architecture holds where it was designed to hold; what has accumulated is
duplication and names that lie.** No structural violation of the Sim seam, no new god class,
no banned pattern the planned milestones don't already count. The real findings are pairs:
two save pipelines, two falloff copies, two repair entry points, two rounding rules for one
number, two vocabularies for one counter — and in every pair, the copies have already begun
to drift.

## Clean

Checked by this pass and not present:

- **The Sim seam holds.** No `UnityEngine` under `Sim/` (M39's audit re-confirmed on today's
  tree).
- **R1 holds everywhere but three named sites** (below) — every other `RunSim` mutator call
  is inside `GameController*`.
- **R2 holds.** No UI file calls `Buy`, `SaveService` or a sim mutator; station purchases
  route through `ShipCommands`.
- **R3 holds.** `SaveService` is called from `GameController*` and `GameSession` only.
- **R4 holds.** No new `FindFirstObjectByType<Player*>`; `PlayerRegistry` is used.
- **No new `Manager`/`Helper`/`Utils` class, no empty Unity message bodies, no
  `FindObjectOfType`.**
- **`RunSim`, `WaveDirector`, `ShipCommands`, `HudController`, `GameController` each have one
  coherent reason to change.** The partial splits are justified shared-state seams, not
  hidden god classes. File sizes are all in cap under M40's counted-line unit.

## Findings — confirmed, and where each one goes

### Scheduled into the re-cut M42 (`Milestones/1. planned/M42-one-mechanism-per-job.md`)

1. **Two save-migration pipelines, already divergent.** `MetaState.ToSaveData/FromSaveData`
   (callers: tests only) and `ToJson/FromJson` (the production path) each implement the
   v3/v4/v6 gates; they disagree on the `-1` ledger sentinel for absent keys
   (`MetaState.cs:418-420` vs `567-569`). Found independently by three lenses. A v7 field is
   a 5-site edit today.
2. **Two falloff copies; the tested one is not the live one.** `WeaponWheel.DamageAtRange` /
   `DamageOnPiercedBody`: 19 test references, zero runtime callers. The live copy
   (`PlayerGun.Firing.ApplyFalloff`) diverges past `def.range` when `falloffStart <= 0` —
   masked only by the ray cap.
3. **Two repair entry points.** `HatchStation.ApplyRepair`: zero call sites, guards
   duplicated from `GameController.RepairHatch`, its own comment says to prefer the command.
4. **The kill log rounds; the bank floors.** `KillLog.Format` prints round-to-nearest while
   `AwardKill` floors (`RunSim.cs:328`); at dial 5 the log says +38, the bank gets 37. The
   kill line is a parsed contract (`4-Testing-and-Determinism.md`).
5. **`TetherSiphon.SalvagePerSecond` survives the cut per-second income** ("the clock never
   pays", `Decisions.md`), kept alive by one test that tests only it. Found by three lenses.
6. **`LossReport` is also the success report** — `CompleteRun` fills it with cause
   `"cleared"`, which its own doc calls "a SUCCESS"; the PlayMode helpers already coined
   "run report" and read the member by reflection string (`RunReportAssertions.cs:36`).
7. **A false comment on the verification surface.** `PlayerHealth.cs:75-78` promises
   ~1 line/second aggregation with a flush; the code logs every hit and no window exists.
   At the 0.7 s swing clock, five gatekeepers ≈ 7 lines/s.
8. **`EffectiveClip` rounds with unstated banker's rounding** (`WeaponWheel.cs:163`) while
   `WaveDirector.cs:150-156` documents `AwayFromZero` for the identical shape; a +1 clip
   purchase can leave the shown clip unchanged with nothing saying why.
9. **`WeaponCatalog`'s "a row here and nowhere else" comment is false** — PRI-C touched five
   runtime files, and the hand-anchored `ArraySize` fails silently when missed
   (`MetaState.SetOwned:233` bounds-checks and returns).
10. **`WaveEmit.Pending` is written twice, read nowhere**, under a comment claiming it
    prevents a softlock it has no part in. **`WeaponDef.abilityDial`** is derived config
    nothing at runtime reads.
11. **The Prep panel re-derives sim income arithmetic** by un-multiplying
    `CurrentKillValue` (`HudController.Panels.cs:87`) — correct only while kill value stays
    purely multiplicative.
12. **16 of 36 Game MonoBehaviours break R5** — 14 `Game/Ui` views unlabeled, `DecoyObject`
    ("HOST-OWNED") and `DecoyBay` ("LOCAL + HOST") using invented vocabulary.
13. **The one-namespace convention is broken three ways in one folder** — 12 files
    `Game.Ui`, 5 files `Game`, `FxColors.cs` `Game.Combat`, against `Architecture.md:19-21`.
14. **Station identity is four raw strings in six places** held together by a comment
    (`ShiftShipUiImport.cs:45-47`, `ShiftFrontEndMutate.cs:34`, four `StationTerminal`
    subclasses, `SceneBuilder.Ship.cs`, `ShipHud.cs`); no test ties them.
15. **`TrySelectSlotPublic`** is a void `TryX` whose extra word states its access level;
    **`PlayerDownAndGrubstakeTests`** advertises a mechanic that exists nowhere; the
    lost-run counter renders as `"death(s)"` (`GameSession.cs:95`) though it increments on
    hatch loss with the player alive.
16. **Two R1 bypasses and one stray Meta write**, each resolved by decision rather than

    WaveSpawner as the caller — the doc gets the sentence, not the code a wrapper);
